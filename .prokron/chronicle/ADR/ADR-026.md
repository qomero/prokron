# ADR-026: Phase specifications are internal; the public documentation leads with the problem
- Date: 2026-09-22
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: ADR-012, ADR-013, ADR-015, ADR-022
- Corrects: none
- Rejects: publishing unbuilt phase specifications alongside shipped behaviour; describing Phase 0 or Phase 3 capability in the README
- Affects: T-DOCS-05
- Context: Four phase specifications sat in `docs/` — two drafts of Phase 0, plus Phase 2 and Phase 3. Only Phase 2 describes anything built. A reader arriving at the repository could not tell a specification for future work from a description of the product, and the two Phase 0 drafts were published without that being a decision anyone made. Separately, the README described the mechanism before the problem: it named seven chronicle files before explaining what a chronicle was, and showed the human view of project state four times while never once showing the agent view that makes its central claim true.
- Decision: Phase specifications are internal working documents and are not published; they live outside the repository, in `next_plan/`, which is ignored. The public documentation is the README, `docs/SPEC.md` and a product thesis, and it is ordered so that the problem comes before the mechanism: why the project loses its own state across sessions and participants, then what Prokron is, then how it works, then the reference material. Both projections of project state are shown rather than asserted — the dashboard for a person, real `prokron context` output for an agent. Anything specified but not built is named as specified and never as available.
- Consequences: ADR-013, ADR-014, ADR-015 and the P2 phase record cite `docs/Phase 2.md` as governing authority, and that document is no longer in the repository. Those citations stay as written, because they were accurate when written and the decisions they record were really taken against that document; the public specification states plainly that the phase specifications are kept outside the repository, so a reader meets an explanation rather than a dead reference. The cost is that an outside reader cannot verify P2's exit against its governing specification, only against the evidence recorded in the chronicle. That was accepted: the chronicle already carries the criteria, the evidence and the audit. Keeping unbuilt specifications public was judged the larger risk, because a specification written as an instruction to an agent reads like a description of an existing feature.

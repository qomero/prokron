# ADR-027: Install with one line, and put the command on PATH
- Date: 2026-09-22
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: ADR-017, ADR-024
- Corrects: none
- Rejects: requiring a mode argument to install; a global runtime shared by every project; editing the reader's shell configuration; creating directories on their machine
- Affects: T-CLI-01
- Context: Installing took `curl -fsSL <raw URL> | sh -s -- existing`, and every command afterwards was typed as `.prokron/prokron status`. Both are artefacts of the tool being private, where nobody weighed the cost of an awkward invocation. `sh -s -- existing` asks a first-time reader to understand shell argument forwarding before they have seen the product, and `existing` is the mode almost everyone wants. A path is not a command: `.prokron/prokron` announces an implementation detail on every line a person types, and it cannot be typed at all from a subdirectory.
- Decision: Installation is `curl -fsSL <raw URL> | sh`, with `existing` as the default mode and `new` still available. The installer also places a small launcher named `prokron` in a directory that is already on the reader's PATH, so the command is `prokron status`. The launcher holds no logic: it walks up from the working directory to the nearest `.prokron/prokron` and execs it, so each repository keeps running its own runtime rather than one global copy, and the guarantee in ADR-017 survives. The installer creates no directories, edits no shell configuration, overwrites no file it did not write, and skips the link entirely when no suitable directory exists — printing the one line a reader can run instead. `--no-link` opts out.
- Consequences: ADR-024 said everything Prokron installs lives in one directory. That still holds for the repository, which is what the promise was about; the launcher is the single exception and it lives on the reader's machine, not in their project. It is one file, it can be deleted, and nothing depends on it — `.prokron/prokron` keeps working and remains what the installed agent instructions use, because an agent may run in a sandbox with a different PATH. A reader who installs Prokron in several repositories gets one command that does the right thing in each. The cost is that a launcher on PATH can go stale if its own format ever changes; it is rewritten on every install, and it contains no version-specific behaviour to go stale.

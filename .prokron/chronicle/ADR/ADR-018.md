# ADR-018: Scope a context packet to its own task
- Date: 2026-09-21
- Status: ACCEPTED
- Authority: evidence from the cold-start experiment for AC-T-P2-13-03
- Supersedes: none
- Amends: ADR-013
- Corrects: none
- Rejects: pasting project narrative into every packet
- Affects: T-P2-13
- Context: `prokron context` embedded `INTENT.md` and `HANDOFF.md` verbatim in every packet. Both describe whatever is in flight, which is usually other work. The first cold-start run handed a real second agent a packet for T-P2-11 alongside intent about T-P2-13 and T-P2-14 and a handoff that contradicted the task's own acceptance classification. The agent refused to start and named the contradiction. It was right to refuse: a reader with no repository cannot tell which of two conflicting statements to believe, and the wrong guess is worse than a question.
- Decision: A packet carries project narrative only when that narrative names the task. It states which task it is for, whether the task is already closed, which dependencies are met, and what currently blocks it. Silence about other work is preferable to a confident irrelevance.
- Consequences: Packets shrank by roughly half. A packet is now self-consistent by construction, which is what makes a cold start possible. The wider project story stays available through `status` and the chronicle, which is where a reader expects it. The experiment also showed that `AC-T-P2-13-02`, recorded PASS on inspection, had been false: inspection by the author missed what a stranger noticed immediately.

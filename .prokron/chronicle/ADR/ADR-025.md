# ADR-025: The dashboard answers from compiled data, never from the drawing
- Date: 2026-09-22
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: ADR-016
- Corrects: none
- Rejects: deriving the dependency chain by walking the rendered SVG's edges; re-implementing the node-identifier rule in JavaScript; shipping a diagram library into the repository to get interaction
- Affects: T-GRAPHVIEW-01
- Context: The task graph had become unreadable — 48 tasks drawn to fit a panel — and nothing on the page said which tasks were connected to which. Making it legible means zoom, pan, and a hover that marks a task's dependency chain. The chain could be read off the drawing, since the edges are right there in the SVG, and that is the shortest path to a working feature.
- Decision: Interaction reads the compiled project embedded in the page and never the rendered diagram. Hovering a task computes its transitive dependencies and dependents from the same `deps` and `blocks` the compiler wrote, so the highlight and `prokron explain` cannot disagree. The map from a Mermaid node identifier back to a task identifier is generated in Python beside the diagrams, because the sanitizing rule lives in `mermaid.py` and a second copy of it in JavaScript would drift. The drawing is used only to find the element to mark.
- Consequences: The page is still one deterministic file with no build step, and Mermaid stays a rendering convenience rather than a source of facts: when it cannot be loaded the page shows diagram source and the rest of the dashboard is unaffected, exactly as before. Marking elements does require knowing how Mermaid names the nodes it renders, which is an internal detail of a pinned major version; that coupling is isolated to the lookup and fails soft, leaving a diagram that simply does not highlight rather than a broken page. The alternative — a diagram library committed to the repository — was rejected because it would put a rendering dependency inside every project that installs Prokron, for a view that is not authority.

# ADR-030: A project names itself in authority, not in the filesystem
- Date: 2026-09-22
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: ADR-014
- Corrects: ADR-016
- Rejects: checking the repository out into a fixed directory name to make the check pass; dropping the project name from compiled output
- Affects: T-NAME-01
- Context: The compiled project took its name from `root.name` — the directory the repository happened to be cloned into. Continuous integration found this on its first run: the same authority compiled to `Prokron` locally and `prokron` on the runner, and three generated files differed. The regeneration claim in Gate B and `AC-T-P2-14-01` had therefore only ever been true within one machine's directory naming, and the wider claim — that two participants reading the same project reach the same answer — was false the moment two people cloned into differently named directories. A local test could not have caught it, because a fixture is always created under one name.
- Decision: A project may name itself with a `Project:` line above the first heading of `PHASES.md`, and that name is what compiles. A chronicle that does not carry one falls back to the directory name, which is where the name always came from, so every existing installation keeps working unchanged and nothing needs migrating. The shipped template carries the field with an empty value, so the next project that installs Prokron is shown the field exists without being forced to fill it.
- Consequences: Compiled output no longer depends on anything outside the chronicle, which is what ADR-014 claimed when it separated authored authority from generated state. The fix was to make the record more complete rather than to make the check less strict — checking out into a fixed directory name in the workflow would have turned a green pipeline into a lie. The cost is one more optional authored field, and a name that is now wrong until someone edits it rather than wrong until someone renames a directory; both are visible in the dashboard header, which is where it would be noticed.

# ADR-019: Migrate v0.1 chronicles explicitly, and never in place
- Date: 2026-09-21
- Status: ACCEPTED
- Authority: defect report from a real project upgrade
- Supersedes: none
- Amends: ADR-011, ADR-014
- Corrects: ADR-014
- Rejects: migrating automatically during installation
- Affects: T-MIGRATE-01
- Context: ADR-014 moved authority from `.prokron/` to `prokron/` and shipped without an upgrade path. A real project updated to 0.2.1 and found its chronicle stranded: every record survived, because the installer preserves what it finds, but the tool read the new location and reported an empty project. Preservation without migration is not continuity; it is a silent loss of the thing the product exists to protect.
- Decision: Provide `prokron migrate`. It reports by default and changes nothing without `--apply`, consistent with ADR-011's rule that upgrades are explicit. It moves tasks, decisions, intent and journal into `prokron/`, converts prose acceptance into contracts with their original wording, splits `DECISIONS.md` into `prokron/ADR/`, and archives every original file unchanged. Installation detects a v0.1 chronicle and names the command, but never migrates on its own: a migration that runs without being asked is indistinguishable from a tool rewriting history.
- Consequences: `TASK_GRAPH.md` is dropped, because it is wholly derivable and the compiler regenerates it. `STATE.md` is not: its risks and next steps are judgement, so that prose moves to `HANDOFF.md` rather than being discarded. Migrated tasks carry `P-NONE`, because v0.1 had no phases and inventing one would fabricate structure the project never agreed to; `--phase` assigns a real phase when one exists. Task completion now counts every task, since excluding phase-independent work made a migrated project report `0 / 0` and look empty.

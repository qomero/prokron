# ADR-029: Continuous integration enforces the project's own invariants
- Date: 2026-09-22
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: ADR-016
- Corrects: none
- Rejects: a workflow that only runs unit tests; publishing a maintainer's email address to receive reports
- Affects: T-CI-01
- Context: Nothing ran this project's tests except a person typing the command. That is tolerable while one contributor works alone and stops being tolerable the moment a change arrives from someone else, because the installer suite is exactly the kind of thing that breaks on a platform nobody checked. Separately, two of this project's central claims are not covered by unit tests at all: that the compiled directory is reproducible from authority, and that authority is internally consistent. Both are checked today only because someone remembers to check them.
- Decision: The workflow runs the unit suite and the installer suite across a matrix of Python versions and both Linux and macOS, and then does two things a normal test job would not. It deletes `.prokron/compiled/`, rebuilds it, and fails if the result differs from what is committed. And it runs `prokron validate` against the real chronicle. The supported Python floor is whatever the matrix proves rather than whatever the README asserts. Reports of security issues and conduct concerns go through GitHub's own private reporting rather than an address published in the repository.
- Consequences: The determinism claim in Gate B and the regeneration claim in `AC-T-P2-14-01` become continuously enforced rather than periodically remembered, and a contributor who hand-edits a generated file or forgets to recompile gets told by the machine instead of by a reviewer. It also settles, by making it load-bearing, the open question of whether `.prokron/compiled/` should stay committed: it stays, because the diff is now the mechanism that proves regeneration. The cost is that every change touching authority carries compiled output in its diff, which is noisy to review; that was already true and is now deliberate. Not publishing an address means reports arrive only through GitHub, which is a real limitation for anyone who will not create an account.

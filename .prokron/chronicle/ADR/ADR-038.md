# ADR-038: Build the baseline ahead of the hierarchy on its own branch
- Date: 2026-09-23
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: ADR-037, ADR-034
- Corrects: none
- Rejects: implementing inside the `cambos-td/work` worktree alongside another agent's uncommitted T-HIERARCHY-01 changes; implementing the hierarchy as part of this task
- Affects: T-BASELINE-01
- Context: ADR-037 deferred implementation until the ADR-035 hierarchy landed, because both touch the parser, validator, and views. The owner then asked for the baseline to be finished now. The `cambos-td/work` worktree holds another agent's uncommitted, idle hierarchy work; mixing a second change into it would produce one review that cannot be separated.
- Decision: Implement T-BASELINE-01 in a separate worktree `../Prokron-baseline` on branch `cambos-td/baseline`, based on `main` at `30c9f37`, against the current task schema. Its dependency on T-HIERARCHY-AUDIT-01 is dropped. The change is proposed to `main` on its own.
- Consequences: The baseline can be reviewed and merged independently. Whichever of the two branches lands second must rebase through the parser, validator, compiled output, and chronicle; the ADR numbering on this branch skips ADR-033 to ADR-036, which exist on other branches, so the numbers stay unique when they meet.

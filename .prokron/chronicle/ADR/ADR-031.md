# ADR-031: Generated views are refreshed on upgrade, and say which version wrote them
- Date: 2026-09-22
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: ADR-011, ADR-017
- Corrects: none
- Rejects: leaving generated views for the reader to refresh; printing an instruction instead of doing the work; stamping every generated file with a version
- Affects: T-UPGRADE-01
- Context: Found by the owner using Prokron on a real project rather than by any test. Installing replaces the runtime but left `.prokron/compiled/` untouched, so an upgraded installation ran a current tool beside a dashboard written by the previous one. The symptom is that a newly released feature appears to be missing, which reads as a broken release rather than a stale file, and nothing on the page said which version produced it. The installer suite could never have caught it: every fixture installs into a fresh directory, so the path where generated output already exists from an older release had never been exercised. ADR-011 established that installation preserves records and does not upgrade guidance; generated views are neither records nor guidance, and were caught by a rule that was not written about them.
- Decision: Installing refreshes the generated views when the installation already has some and the chronicle holds work — which is exactly the upgrade case, and never a fresh install, where compiled output is still created only by compiling. Refreshing is safe because the views are reproducible from authority by definition, so nothing authored is at risk. If the refresh cannot run, because authority does not validate or no interpreter is present, the installer says so and prints the command rather than failing the installation. Separately, `project.json` records the version that compiled it, and `status` reports when that differs from the running tool, so a stale installation is visible to anyone who never reinstalls.
- Consequences: Upgrading now produces a consistent installation rather than a new tool beside an old page. The version in `project.json` means a release that bumps `VERSION` changes compiled output, so the continuous-integration check added in ADR-029 will now also catch a release that forgot to recompile — noisier diffs, deliberately. Only `project.json` carries the stamp, not every generated file, so the noise is one line rather than four files. The deeper lesson is recorded rather than only the fix: this class of defect lives in the difference between a fresh install and an upgrade, and the suite only tested one of them.

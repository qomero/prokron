# ADR-021: Address the GitHub owner by its current name, never by redirect
- Date: 2026-09-22
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: none
- Corrects: none
- Rejects: relying on GitHub's rename redirect for installation URLs
- Affects: T-RENAME-01
- Context: The owner account was renamed from `qomerovn` to `qomero`. GitHub redirects the old owner path, so `install.sh`, the README command, the tarball URL and the raw URL all kept working and nothing appeared broken. That is precisely the hazard. A freed GitHub username is claimable by anyone, and the moment `qomerovn` is registered the redirect stops pointing at this project. The README's primary instruction pipes that URL into `sh`, so a stale owner name in an installer is not a cosmetic inaccuracy; it is an unattended handover of code execution to whoever takes the abandoned name.
- Decision: Every network path in the repository addresses the owner by its current name. The previous name survives only in `JOURNAL.md`, which is append-only and records what was true when it was written. Redirects are treated as a migration convenience with an expiry nobody controls, never as an address. The README now documents the anonymous `curl` install as the default, because the repository is public, and tells the reader to read the script before piping it to a shell.
- Consequences: A future rename requires the same sweep, and the acceptance contract for this task states where to look. The GitHub CLI install is kept as an alternative rather than the default, since it no longer carries the access requirement that made it primary while the repository was private.

# ADR-023: Attribute commits by an address on the owning account
- Date: 2026-09-22
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: none
- Corrects: none
- Rejects: changing only the author name string; keeping an address registered to a different account
- Affects: T-AUTHOR-01
- Context: The repository's history named two different authors, and correcting the name looked like the whole fix. It was not. GitHub attributes a commit by its email address, so every commit here — including the seven that already carried the current name — resolved to a different account that happens to hold the address they were written with. A name string is a label; the address is the identity. The address could not simply be moved either, because GitHub does not allow one address on two accounts, and removing it from the other account would have un-attributed that account's unrelated history.
- Decision: Commits are authored with an address verified on the account that owns the repository, and the existing history was rewritten to match rather than left inconsistent with it. The identity is set repository-locally, so it does not depend on a global setting that another project may change. Before the published history was rewritten, a throwaway branch confirmed that the address resolved to the intended account.
- Consequences: Every commit hash changed and `main` and all six version tags were force-pushed, so any existing clone has a diverged history and must reset. That cost was accepted for a project at this size with a single contributor. The pre-rewrite tip is kept on a local branch rather than published, so the old history is recoverable here but is not carried in the repository. The verification step is the part worth repeating: checking attribution on a throwaway ref first meant the published history was rewritten once instead of twice.

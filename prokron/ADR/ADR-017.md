# ADR-017: Ship the runtime as copied files beside the chronicle
- Date: 2026-09-21
- Status: ACCEPTED
- Authority: implementation choice under ADR-013 and ADR-016
- Supersedes: none
- Amends: ADR-009, ADR-016
- Corrects: none
- Rejects: publishing the runtime as an installable package for Phase 2
- Affects: T-P2-06
- Context: ADR-013 restores a deterministic runtime and ADR-016 forbids third-party dependencies, but ADR-009 established a shell bootstrap that copies files rather than installing software. A package on an index would reintroduce the release and versioning burden that ADR-008 removed, and would make the tool's version drift from the chronicle it compiles.
- Decision: The installer copies the runtime into `.prokron-runtime/prokron/` and an executable shim into `bin/prokron`. Records are preserved on reinstall; the runtime is replaced on every install, because a stale compiler reading a current chronicle is worse than no compiler. The repository's own copy lives in `src/prokron/` and the shim resolves either location.
- Consequences: A repository needs only a Python interpreter. There is no package, no lock file, no virtual environment, and no upgrade command. The installer must copy every runtime module, so a regression check asserts that the shipped module list matches the source directory. `.prokron-runtime/` is code and is distinct from `.prokron/`, which stays compiled output and stays disposable.

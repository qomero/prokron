# ADR-022: Lead with project management, and show the product rather than describe it
- Date: 2026-09-22
- Status: ACCEPTED
- Authority: product owner
- Supersedes: none
- Amends: ADR-012
- Corrects: none
- Rejects: presenting Prokron primarily as agent session continuity
- Affects: T-DOCS-04
- Context: ADR-012 moved the public framing from session handoff to shared understanding between people and AI, which was right at the time and is no longer complete. Phase 2 shipped a deterministic compiler, acceptance contracts, phases, gates, obstacles, a critical path and a dashboard. What the project now does is project tracking and project management, and the fact that an agent and a person read the same record is how it does it rather than what it is for. The README still described a six-file Markdown convention, quoted stale figures from a compile several releases old, and showed none of the generated output, so a reader had to take the central claim on faith.
- Decision: The README leads with project management a person can use, and treats the shared human and AI language as the mechanism that makes it trustworthy rather than as the headline. Claims that can be shown are shown: real screenshots of the generated dashboard, real command output copied from a current run, and this repository's own unfinished work left visible rather than cropped out. Every figure quoted in the README comes from a compile of the chronicle as committed, and the screenshots are captured from that same compiled dashboard.
- Consequences: The README carries four binary images, which is a maintenance cost: a change to the dashboard layout or a material change in project state makes them stale, and they must be recaptured from a fresh compile rather than edited. That cost is accepted because a project management tool that cannot show its own output asks the reader to trust a description of a screen. ADR-012's substance stands — people and AI share one record — but it is now stated as a property of the system rather than as the opening claim.
